# LVGL Pro Editor: first steps with the stock watchlist design

`lvgl_pro_ui/` is an LVGL Pro Editor 2.0.x project that draws the same two screens as the
hand-written firmware in `main/ui/`. Both follow [`ui-spec.md`](ui-spec.md)
(revision 3).
This guide covers opening the project, how it matches the device, a first exercise, what
the export produces, and how the export will go into the firmware.

Docs: <https://lvgl.io/docs/pro>. The widget XML API is at
<https://lvgl.io/docs/pro/built_in_widgets>, and the schema files are in
[lvgl_widgets_xml/v9.5.0](https://github.com/lvgl/lvgl_pro/tree/v2.0.5/lvgl_widgets_xml/v9.5.0).

## a) Open the project

1. Start the AppImage from `~/Downloads/LVGL_Pro_Editor-2.0.5-linux/`. If it stops with a
   GTK error, start it from a terminal with `--gtk-version=3`
   ([Installation](https://lvgl.io/docs/pro/editor/installation)).
2. Choose **File > Open Folder** and pick `lvgl_pro_ui/` in this repo, the
   folder that holds `project.xml`.
3. Open `screens/screen_watchlist.xml` from the Explorer.

The window is a VS Code-like editor ([Editor overview](https://lvgl.io/docs/pro/editor/overview)):

| Part | What it does |
| --- | --- |
| Explorer (left) | The project files. One XML file is one screen or component. |
| XML editor | The source. Ctrl+Space autocompletes tags and attributes. Ctrl+Up/Down nudges the number under the cursor by 1 (add Shift for 10). Ctrl+click a tag such as `<stock_row>` to open its file. |
| Live preview | Real LVGL rendering of the open file at 480x480. It updates as you type. Ctrl+wheel zooms. A component file is previewed with the sizes in its `<previews>` block. |
| Code / Design toggle (top of the window) | Design mode edits the same files with drag and drop. For a component instance it shows only that component's `<api>` props. |
| Preview toolbar | **Inspector**, **Connect to Figma**, and the hammer (**Compile and export code**, the same as Ctrl+B). |
| Inspector mode | Toolbar button, or hold Alt over the preview. It shows size, padding, margins and the click area. Click an element to jump to its XML, double-click to open its component. |

Where things are:

| File | Contents |
| --- | --- |
| `project.xml` | Display size, LVGL version, theme |
| `globals.xml` | Colour and size constants, fonts, shared styles |
| `components/stock_row.xml` | One row: props `symbol`, `full_name`, `last`, `change`, `change_pct`, `trend_color` |
| `components/app_header.xml` | Watchlist header: props `title`, `title_color`, `status`, plus the speed slider and its readout |
| `components/stats_cell.xml` | Caption and value: props `caption`, `value` |
| `components/box.xml` | Plain container without theme styles (like `ui_box_create()`) |
| `screens/screen_watchlist.xml` | Header, captions, the list and its two edge fades |
| `screens/screen_detail.xml` | VALE3 with the chart and the stats grid |

Syntax in one paragraph: `#name` is a constant, `$name` is a prop of the component you are in,
and `<style name="style_x" selector="pressed"/>` adds a shared style for a state or part.
`style_bg_color-indicator="..."` sets one style property for one part. XML needs escapes for
`'`, `"`, `<` and `&`. See [Overview](https://lvgl.io/docs/pro/syntax/overview),
[Components](https://lvgl.io/docs/pro/syntax/components), [API](https://lvgl.io/docs/pro/syntax/api),
[Styles](https://lvgl.io/docs/pro/syntax/styles) and [Constants](https://lvgl.io/docs/pro/syntax/constants).

## b) How the project matches the device

| Device / firmware | In this project |
| --- | --- |
| 480x480 panel | `project.xml`: `<display width="480" height="480"/>` |
| LVGL 9.5.0 (`lvgl/lvgl: "9.5.0"` in `main/idf_component.yml`) | `project.xml`: `lvgl_version="9.5.0"`, so the editor uses the 9.5.0 widget API |
| 16-bit colour, RGB565 (`CONFIG_LV_COLOR_DEPTH=16`) | Not an XML setting. The exported C works at any depth. `sim/lv_conf_sdl.defaults` sets `LV_COLOR_DEPTH 16` so the F5 simulator matches the panel. If you add images later, pick their `color_format` with RGB565 in mind. |
| `lv_theme_default` in dark mode | The preview uses the light default theme. Every colour that shows is set in the XML, so the difference isn't visible. |
| Fonts compiled into the firmware | Declared in `globals.xml` and generated by the export (next section) |

**Fonts.** The firmware has only the fonts compiled into it: Montserrat 14 is the only
built-in LVGL font enabled in `sdkconfig`, plus your own. So every font the UI uses must be
declared in the `<fonts>` block of `globals.xml`. Ctrl+B then turns each one into a C file
(`fonts/font_14_data.c`, ...). Don't use LVGL's `lv_font_montserrat_*` names in the XML.
`font_12`, `font_14`, `font_16`, `font_18`, `font_20`, `font_24` and `font_40` are Montserrat Medium, `bpp="4"`, with
ASCII + Latin-1 (`0x20-0x7E,0xA0-0xFF`) and the same few typographic characters as the
firmware fonts. Characters outside the range don't render, so add them to `range` first.
See [Fonts](https://lvgl.io/docs/pro/syntax/fonts).

**Icons (LV_SYMBOL_\*).** LVGL's symbols are Font Awesome glyphs at private code points, for
example `LV_SYMBOL_WIFI` is U+F1EB. A `<bin>` font has a single `src_path`, so the icons are
a second set of fonts, `icons_12` ... `icons_40`, built from `fonts/FontAwesome5.ttf`. Each
`font_N` names its icon font as a fallback with `lv_fallback="icons_N_data"`, which is the
C symbol the export generates for `icons_N`. That way one label in `font_N` can mix text and
icons, like the firmware's merged fonts. This is exactly how the editor's own "basic"
template gives its keyboard the arrow and OK keys. The icon-only label of the back button
uses `icons_20` directly. In XML text, write the code point as a character reference:

| Symbol | Code | XML |
| --- | --- | --- |
| WIFI | F1EB | `&#xF1EB;` |
| WARNING | F071 | `&#xF071;` |
| LEFT | F053 | `&#xF053;` |

The icon fonts also have OK, CLOSE, PLAY, PAUSE, RIGHT, PLUS, TRASH, KEYBOARD, BACKSPACE,
NEW_LINE, REFRESH, UP and DOWN, the same set as the firmware fonts. To add another symbol, look
up its code in `lvgl/src/font/lv_symbol_def.h` and add it to the `range` of all seven `icons_N` fonts.

**Kconfig options the exported code needs.** Set them with `idf.py menuconfig` >
Component config > LVGL configuration:

| Option | Why |
| --- | --- |
| `CONFIG_LV_USE_OBJ_NAME=y` (Feature Configuration > Others > "Enable support widget names") | **Required, and currently off in the firmware.** The 2.0.x export calls `lv_obj_set_name_static()` on every created root and `lv_obj_set_name()` on every named object (see `lvgl-editor-examples/tutorials/screens/hello_world/screen_hello_world_gen.c`). LVGL 9.5 only declares these when `LV_USE_OBJ_NAME` is 1. It also gives you `lv_obj_find_by_name()`. |
| `CONFIG_LV_COLOR_DEPTH_16=y`, `CONFIG_LV_USE_CHART`, `_LABEL`, `_BUTTON`, `_SLIDER`, `CONFIG_LV_USE_FLEX` | Already on. Keep them. |
| `CONFIG_LV_USE_OBSERVER` | Only if you add `<subjects>` (data binding). Already on. |
| `CONFIG_LV_USE_TRANSLATION`, `CONFIG_LV_USE_FLOAT`, `CONFIG_LV_USE_TINY_TTF`, file systems | Not needed: no translations, float subjects, TTF fonts or file-based assets here. |

## c) A 10-minute first exercise

1. **Change a colour constant (2 min).** Open `screens/screen_watchlist.xml` so the preview
   shows the list. In `globals.xml`, change `color_down` from `0xF85149` to `0xFF00FF` and
   save with Ctrl+S. Every negative change, pill and the detail chart turn magenta, because
   they all use `#color_down`. Change it back.
2. **Add a row (3 min).** In `screen_watchlist.xml`, inside `<box name="list">`, add a line
   (made-up numbers):
   ```xml
   <stock_row symbol="PETR4" full_name="Petrobras PN" last="37.10" change="+0.45" change_pct="+1.23%" trend_color="#color_up" />
   ```
   Drag in the preview to scroll to the bottom of the list. Here it is a plain list that
   stops at the last row; the endless wheel is firmware code (section e). Try a very long
   `full_name`: it wraps to a second line and then ends with dots, because the label is
   `#name_width` wide with a fixed 2-line height (`#name_height`). Ctrl+click `stock_row` to
   see how the row is built.
3. **Drag a widget in Design mode (5 min).** Open `screens/screen_detail.xml` and switch the
   toggle to **Design**. Drag the price label `61.49` or the chart, then switch back to
   Code: its `x`/`y` attributes changed. Undo with Ctrl+Z. Rows in the list and cells in the
   stats grid sit in flex layouts, so they are placed by the layout and don't move freely.
   Hold Alt over the chart to see its size and padding in the inspector.

## d) What Ctrl+B produces

**Ctrl+E** only exports the C code. **Ctrl+B** exports and also compiles the preview. The first
Ctrl+B downloads EMSDK 4.0.6 and needs `git` and `make` installed. This project has no
custom C widgets, so the preview works without compiling and Ctrl+E is enough to get the C.
See [Hotkeys](https://lvgl.io/docs/pro/editor/hotkeys).

The C files appear next to the XML files:

| Files | Kind |
| --- | --- |
| `stock_ui_gen.c/.h` | Generated from `globals.xml`: constants as macros (`COLOR_DOWN`, `ROW_HEIGHT`, ...), the fonts as `lv_font_t * font_14` pointers, global styles, and `stock_ui_init_gen()`. The header includes every component and screen header. |
| `components/*_gen.c/.h`, `screens/*_gen.c/.h` | Generated, one create function per file |
| `fonts/*_data.c` | Generated font bitmaps |
| `CMakeLists.txt`, `file_list_gen.cmake`, `component_lib_list_gen.cmake` | Generated. They build the `lib-ui` CMake library. `file_list_gen.cmake` lists every `.c` file. |
| `stock_ui.c/.h`, `user_config.cmake`, `sim/main.c` | User files. They are created once and never overwritten, so your code goes here. |

**Never edit** `*_gen.c`, `*_gen.h`, `fonts/*_data.c`, `CMakeLists.txt`, `file_list_gen.cmake` or
`component_lib_list_gen.cmake`: every export overwrites them. Change the XML instead.
`preview-bin/` belongs to the editor.

The C API you will get (from the docs and the examples' exported code, so check `stock_ui_gen.h`
after the first export):

```c
void stock_ui_init(const char * asset_path);          /* call once, before any create */
lv_obj_t * screen_watchlist_create(void);
lv_obj_t * screen_detail_create(void);
lv_obj_t * stock_row_create(lv_obj_t * parent, const char * symbol, const char * full_name,
                            const char * last, const char * change, const char * change_pct,
                            lv_color_t trend_color);
lv_obj_t * app_header_create(lv_obj_t * parent, const char * title, lv_color_t title_color,
                             const char * status);
lv_obj_t * stats_cell_create(lv_obj_t * parent, const char * caption, const char * value);
```

Objects with a `name` in the XML can be found from C, for example
`lv_obj_find_by_name(row, "lbl_last")`. Names used: `header` with `lbl_title`, `slider_speed`,
`lbl_speed` and `lbl_status`, then `list`, `fade_top`, `fade_bottom` (watchlist);
`lbl_symbol`, `lbl_name`, `lbl_last`, `lbl_change`, `pill`, `lbl_pct` (row); `btn_back`,
`lbl_symbol`, `lbl_name`, `lbl_price`, `lbl_change`, `chart`, `stat_open` ... `stat_time` with
`lbl_value` (detail).
See [Using exported C code](https://lvgl.io/docs/pro/integration/using-exported-c-code) and
[CMake](https://lvgl.io/docs/pro/integration/cmake).

**F5** runs the same C in the PC simulator (`sim/`, needs `libsdl2-dev`, CMake, Python 3).
`sim/main.c` loads `screen_watchlist_create()`. See
[Simulator](https://lvgl.io/docs/pro/integration/simulator).

## e) Next step: putting the export into the firmware

The plan, not done yet.

**The wheel stays in C.** The firmware shows the list as an endless wheel: it glides
continuously at the header slider's speed (stopped .. 1.0x), pauses while touched and resumes
5 s after the last touch. That is C code in `main/ui/ui_watchlist.c`, which moves rows between
the two ends of the list as it scrolls. A static design can't show it, so the export only
provides the widgets: `list` (flex column, no scroll bar, rows snap to the top), the rows, the
fades and the slider. Keep the wheel code and point it at the exported `list`.

1. Enable `CONFIG_LV_USE_OBJ_NAME=y`, with menuconfig or by adding it to `sdkconfig.defaults`
   and deleting `sdkconfig` so it is regenerated.
2. Add a wrapper component, `components/ui/`, that compiles the exported
   files where they are:

   `components/ui/CMakeLists.txt`
   ```cmake
   # The LVGL Pro project; export it with Ctrl+B / Ctrl+E first
   set(UI_DIR "${CMAKE_CURRENT_LIST_DIR}/../../lvgl_pro_ui")

   set(LV_EDITOR_PROJECT_SOURCES "")
   include("${UI_DIR}/file_list_gen.cmake")   # every exported .c file, plus stock_ui.c
   include("${UI_DIR}/user_config.cmake")     # your extra sources, if any

   idf_component_register(SRCS ${LV_EDITOR_PROJECT_SOURCES}
                          INCLUDE_DIRS "${UI_DIR}")

   # The exported headers include "lvgl.h" (not "lvgl/lvgl.h") only with this define
   target_compile_definitions(${COMPONENT_LIB} PUBLIC LV_LVGL_H_INCLUDE_SIMPLE)
   ```

   `components/ui/idf_component.yml`
   ```yaml
   dependencies:
     lvgl/lvgl:
       version: "9.5.0"
       public: true
   ```
3. Remove the old fonts: drop `fonts/font_*.c` from `main/CMakeLists.txt` and the
   `LV_FONT_DECLARE(font_*)` lines from `ui_theme.h`. The export defines `font_14` etc. itself,
   as `lv_font_t *` pointers, so keeping both fails to link. Use `font_16` where the old code
   had `&font_16`, for example in `ui_theme_init()`.
4. Build the UI from the exported functions, holding the display lock as `main.c` does now:

   ```c
   #include "stock_ui.h"

   bsp_display_lock(0);
   ui_theme_init(display);             /* keep LVGL's dark default theme (message boxes) */
   stock_ui_init("");                  /* fonts and global styles; all assets are compiled in */
   lv_obj_t *scr = screen_watchlist_create();
   lv_obj_t *list = lv_obj_find_by_name(scr, "list");
   lv_obj_clean(list);                 /* drop the sample rows */
   lv_obj_t *row = stock_row_create(list, "VAMO3", "Vamos Locacao", "--", "--", "--", COLOR_FLAT);
   lv_screen_load(scr);
   bsp_display_unlock();
   ```
5. Update the widgets from C. In an `lv_timer`, which runs in the LVGL task like today's
   250 ms `ui_tick`, no lock is needed. From any other task, wrap the calls in
   `bsp_display_lock(0)` / `bsp_display_unlock()`:

   ```c
   bsp_display_lock(0);
   lv_label_set_text(lv_obj_find_by_name(row, "lbl_last"), "6.28");
   lv_obj_set_style_text_color(lv_obj_find_by_name(row, "lbl_change"), COLOR_DOWN, 0);
   lv_obj_set_style_bg_color(lv_obj_find_by_name(row, "pill"), COLOR_DOWN, 0);
   bsp_display_unlock();
   ```
   The title works the same way: `lv_label_set_text()` on `lbl_title` with "Stonks!",
   "Not stonks..." or "Stonks?", and its text colour set to `COLOR_UP`, `COLOR_DOWN` or
   `COLOR_FLAT`. Events stay in C as well:
   `lv_obj_add_event_cb(row, on_row_clicked, LV_EVENT_CLICKED, ...)`, and `on_speed_changed` on
   `slider_speed` for `LV_EVENT_VALUE_CHANGED` and `LV_EVENT_RELEASED`, which sets the roll speed
   and the `lbl_speed` text ("1.5x", or "Stop" at 0). The design's value is 3 ("0.3x"), so set
   the slider and the readout from the saved speed after creating the screen.
6. For smooth fades, delete the bands from C (`lv_obj_clean(fade_top)`) and give `fade_top` and
   `fade_bottom` the gradient that `ui_watchlist.c` uses: `bg_grad_dir` ver, `bg_color` and
   `bg_grad_color` `COLOR_BG_SCREEN`, plus `lv_obj_set_style_bg_main_opa()` /
   `lv_obj_set_style_bg_grad_opa()`, which the XML can't set (see "Known differences" at the end).

## f) Troubleshooting

| Problem | Fix |
| --- | --- |
| The Wi-Fi icon in the status label is an empty box in the preview, but the back icon shows | The preview isn't applying `lv_fallback`. Press Ctrl+B once. If that doesn't help, replace `lv_fallback="icons_N_data"` with `fallback="icons_N"` (the form on the [Fonts](https://lvgl.io/docs/pro/syntax/fonts) page) in the seven `font_N` entries. |
| An icon or accented letter is missing | Its code point isn't in the font's `range`. Add it to `font_N` (letters) or to all `icons_N` (icons). |
| A long name runs past its lines instead of ending with dots | `long_mode="dots"` needs a fixed height: `#name_height` (2 lines of `font_12`) in a row, `#caption_line_height` (1 line of `font_14`) on the detail screen. |
| The preview shows an error or nothing | The editor validates as you type, so read its message. It is usually an attribute that doesn't exist (check the widget page under [Built-in widgets](https://lvgl.io/docs/pro/built_in_widgets)), a `#const` or font name typo, or an unescaped `'`, `<` or `&`. |
| The first Ctrl+B fails | It installs EMSDK and needs `git` and `make`. Use Ctrl+E to export without compiling. |
| The AppImage doesn't start | Run it from a terminal with `--gtk-version=3`. |
| Firmware: `implicit declaration of lv_obj_set_name_static` | Set `CONFIG_LV_USE_OBJ_NAME=y`. |
| Firmware: `lvgl/lvgl.h: No such file` | Add the `LV_LVGL_H_INCLUDE_SIMPLE` definition (step e.2). |
| Firmware: `multiple definition of font_14` | Remove the old `main/fonts/font_*.c` (step e.3). |
| Firmware: undefined `lv_translation_*` | The export emits translation code for a `translations.xml` (this project has none). Delete that file, or enable `CONFIG_LV_USE_TRANSLATION`. |

**Known differences from the firmware.** The list is a plain list that stops at the last row,
not the endless gliding wheel (section e). The edge fades are stacks of bands (6 for the
12 px top fade, 8 for the 40 px bottom one) with falling opacity, not smooth gradients: the
v9.5.0 schema has `bg_grad_dir` and `bg_grad_color` but no `bg_main_opa` or `bg_grad_opa`, so
an XML style can only blend two opaque colours. The `<gradients>` block in the
[Styles](https://lvgl.io/docs/pro/syntax/styles) docs isn't in the schema either, and the docs
say the preview doesn't render it.
